Your memorandum · Walls

Wall thickness and drawing defaults

Walls · BOS-01, BOS-02

When starting a wall, I should be able to select a 220 mm wall and continue drawing with that thickness until I choose a different wall type.

The same should apply to the wall reference line. Once I select the centreline, inner face or outer face, the system should retain that setting for subsequent walls.

These selections should become the active drawing defaults. Starting another wall should not reset the thickness to 110 mm or change the reference line without my instruction.

At present, switching from a 110 mm wall back to a 220 mm wall appears to restore the default settings. Please check that changing the wall type does not also reset the selected reference line.

Implemented

Action:

Choosing 220 mm (or any wall type), leaving the wall tool, and starting Walls again keeps that type. Centre, exterior face, and interior face stay selected the same way. Changing from 110 mm to 220 mm does not clear the location line.

Walls · BOS-03

The wall description shows a thickness of 220 mm, but the measured width appears to be 240 mm. Please investigate this discrepancy so that the description, drawn geometry and measured quantity agree.

Implemented

Action:

The plastered masonry wall stores two thicknesses. The masonry core is 220 mm. The wall on the plan, face to face, is 240 mm. The 20 mm between them is plaster, and the type reads 220 mm masonry + plaster (240 mm overall). The 110 mm plastered wall and the plastered pool wall are named the same way.

  • The stroke, the location line, a face-to-face measure, and the masonry quantity use the overall width.
  • Plaster stays its own coat on the bill. Paint does not thicken the wall.
  • A foundation that is not plastered is labelled with its overall thickness only. It is not described as plaster.

Walls · BOS-04

Can the user duplicate an existing wall type and edit its thickness to create a new type? For example, a 220 mm wall could be used as the starting point for a 280 mm wall. The new type should remain available for use and be identifiable in the BOQ.

Blocked

Action:

We agree this is useful. Wall types today come from the firm catalogue, not from in-app authoring. We need product-owner approval before users can duplicate and edit types.

Needed to unblock: decision that user-authored wall types are in scope for this app.

Walls · BOS-05

My preliminary suggestion is to link the wall family to the relevant BOQ line item, while retaining the dimensions of each wall type. We still need to refine this approach so that walls requiring different descriptions or rates are not grouped incorrectly.

Blocked — needs discussion

Action:

Each wall SKU already carries a rate reference for the bill. The open question is how walls roll up on the client summary when descriptions or rates differ.

Needed to unblock: your confirmed grouping rule (which walls may share one bill line).

Walls · BOS-06

New walls should display in red by default, while existing walls remain white. Preferably, the user should be able to set the colour for a particular wall family without changing unrelated families.

Implemented

Action:

New walls draw red; existing walls draw white with a dark outline so they stay visible on the sheet. Colour per wall family is not planned: pack colour is a material class, and changing it for one family would not be a free picker. Doors, windows, and other families keep their own colours.

Walls · BOS-07

Snap controls should be visible when they are needed, including when selecting or editing an existing wall. Could a contextual control appear above the selected wall, allowing the user to snap accurately or split the wall into two sections?

Implemented

Action:

With exactly one wall selected, Snap and Split sit beside the run. Snap uses the same magnets as drawing; split takes a click on the wall. Openings and finishes stay on the correct piece after a split.

Walls · BOS-08

Walls should follow the selected angle or alignment precisely. The current drawing behaviour appears to allow a wall to sit slightly off the intended line. Even a small angular error can create significant problems with dimensions, junctions and the overall layout.

Implemented

Action:

While drawing, direction is chosen before length. Runs near an axis or an existing wall store on that line. Typing length or heading no longer tilts the wall by rounding X and Y separately.

Sheets · BOS-09

After drawing the walls, I need to see where garage doors, doors and windows belong on the underlying plan. My preference is for the relevant opening on the PDF to remain visible when I select a wall. A toggle between the PDF and the modelled walls could provide an additional way to check alignment.

Implemented

Action:

Selecting a wall no longer hides underlay openings. Model puts drawn walls on top; Sheet puts the PDF on top. Opacity control is unchanged.

Walls · BOS-10

If a wall has been drawn using the wrong reference line, I should be able to select it and correct its alignment by choosing the centreline, inner face or outer face. The centreline option is particularly important when designing on a grid.

Implemented

Action:

Select a wall and switch location line. The wall shifts so the chosen line stays where the old one was; joins at both ends stay closed. Centreline is included for grid work.

Your memorandum · Floors

Floors, undo, move, alignment

Floors · BOS-11

Floors should be created either by selecting a room or by sketching a boundary. For a typical ground floor, the user may draw one floor across the full footprint. Its boundary should remain linked to the external walls so that moving a linked wall updates the floor. The same principle should apply to an upper-floor slab or roof where that relationship is intended. If the layout changes substantially, for example by adding a new wall, the user must also be able to edit the boundary manually.

Queued — wave 4

Action:

A room can already take its outline from the walls around a seed. A slab or roof is still a rectangle and is not tied to the external walls. The queued work is that link: moving a linked wall updates the floor, an upper slab or roof can use the same link, and the link can be dropped so the boundary is edited by hand.

Floors · BOS-12

The corner-editing control is useful, but I should also be able to select an individual boundary line and move or amend it directly, without having to rebuild the entire floor outline.

Implemented

Action:

Select the floor (not a finish on it). Line picks one edge and drags it; other corners stay put. Corner handles and Corner to add a point still work.

Floors · BOS-13

Please add an Undo control so that an incorrect drawing or editing action can be reversed.

Already in the product

Action:

Undo is on the toolbar. If you find an action that cannot be reversed, name it and we will treat that as a separate fix.

Floors · BOS-14

Please add a Move control for repositioning items such as an imported PDF, a wall or a tiled area. The user should be able to select the item and move it accurately.

Implemented

Action:

Modify → Move repositions one selected wall, the selected sheet, or the tiled area being edited. Snap and typed distance match wall drawing; the move is one undo step.

Floors · BOS-15

It is difficult to align the two floor levels. Although both drawings have been scaled and display the same dimensions, the underlying walls do not line up. Please check the scaling and alignment workflow and provide a reliable way to snap corresponding reference points together.

Implemented

Action:

Pick the same reference point on each level (for example a building corner). Sheets and walls drawn from them share that point. Alignment moves position; it does not change stored wall lengths except where you scale.

Your memorandum · Doors

Door placement

Doors · BOS-16, BOS-17

When placing several doors, the system should retain the previously selected door until I choose another type. I should not have to reopen the full library after every placement. As discussed, please add a Recently Used row at the bottom of the library so that frequently used doors can be selected quickly.

Implemented

Action:

After one door is placed, that type stays ready until you pick another or leave the tool. The library shows a Recently used row for this session; it does not replace the full catalogue.

Your memorandum · Sewer lines

Service line colours

Services · BOS-18

Sewer lines should use the appropriate line colours so that the services are easy to distinguish on the drawing. I will provide the required colour conventions for implementation.

Blocked

Action:

Drainage, cold and hot water, electrical, and gas already use distinct colours. Soil, waste, and vent will follow your convention when we have it.

Needed to unblock: colour convention list from you.

Your memorandum · Electrical

Boards, circuits, sockets

Electrical · BOS-19

Electrical lines should connect the relevant lights and other points to a distribution board (DB), with each circuit associated with a breaker. We can later consider rules that limit the load on a circuit. Because the system will also serve electricians, it should allow them to build up the DB and circuit information. When the first electrical point or line is placed, the system could prompt the user to locate the DB. Alternatively, the user could place the DB later and then link the circuits. The model must allow more than one DB, including separate boards serving different floors.

Queued — wave 4 (last in wave)

Action:

Electrical is drawn as a network today; there is no board, breaker, or circuit object yet. This is the largest item in the current queue. Load limits and auto-routing are explicitly out of scope for this step.

Electrical · BOS-20

Can plug points automatically attach to the relevant surface? Wall sockets should sit against the selected wall, while floor sockets should be positioned within the selected floor. Their placement should remain tied to that surface so that they do not float in mid-air.

Implemented

Action:

Wall plugs (single, double, shaver) store the wall and face they were clicked on, and they move with that wall. In the catalogue, the floor-hosted fittings are floor lights, recessed floor lights, and underfloor heating: those stay inside the selected floor. A wall or floor fitting with no surface is refused. Ceiling plugs, slab plugs, and switches stay free points — they are not tied to a wall or floor.

Electrical · BOS-21

Can each plug point also be linked to the appropriate DB, with a proposed cable route generated automatically? Where more than one DB is present, the user should be able to confirm which board serves the point.

Blocked

Action:

Hand-drawn electrical runs already exist. Automatic routing is a product decision, and it waits on distribution boards (BOS-19). Where there is more than one board, the user would confirm which board serves the point — that is part of the feature, not a separate blocker.

Needed to unblock: agreement to generate cable routes (today services are placed symbols and provisional sums, not routed cables).

Your memorandum · Columns

Columns and structural steel

Columns · BOS-22

I need round and square column options with editable dimensions. The dimensions should be entered directly into input fields and reflected immediately in the drawing. Selecting a column in the drawing should also display its current dimensions and allow them to be changed.

Queued — wave 4

Action:

Columns today are fixed catalogue sizes. Next: round and square placement with live width, depth, or diameter fields and inspector edit on selection.

Columns · BOS-23

How will these columns be described and measured in the BOQ? They cannot all be treated in the same way as walls. The system needs to distinguish the section shape, material, external dimensions and, where applicable, steel wall thickness. For example, steel tubes may have wall thicknesses of 3, 6, 10 or 12 mm, as well as different external dimensions.

I can provide a list of standard square tube sizes for the library. We will also need I-sections, which may be used as either columns or beams. The selected section and its use should remain clear in the drawing and the BOQ.

Blocked

Action:

Bill logic for tubes and I-sections waits on editable columns and your standard tube list.

Needed to unblock: standard square-tube list; BOS-22 done so shape, material, outer size, and wall thickness can be stored.

Your memorandum · Wall finishes

Guidelines and paint on the bill

Finishes · BOS-24

Can we add a guideline measured down from the top of the wall so that finish boundaries can be drawn accurately? The user should be able to enter the offset and use that line to define the extent of a finish.

Implemented

Action:

On the wall elevation, type millimetres down from the top; a guideline appears and finish boundaries can be drawn to it. Quantities and bill mapping are unchanged.

Finishes · BOS-25

When I select paint, the system does not appear to display the corresponding finish from the BOQ. Can this link be enabled so that the selected finish can be identified on the drawing and traced to the relevant BOQ item?

Implemented

Action:

Selecting paint shows which bill item it prices as, on the panel and in the compiled bill. No product chosen → PC allowance label; no rate in the book → gap shown, not invented.

Your memorandum · Final product

Client costing document

Client document · BOS-31

The builder should be able to give the client a detailed costing document that identifies the tile finish for each area. For example, the kitchen wall above the cupboards may require a 750 mm-high band of mosaic tiles, while the remaining scullery walls require porcelain tiles. These finishes carry different costs, so their locations, extent and specifications must be clear.

Queued — wave 4

Action:

The model can hold two finishes on one wall; the client document does not yet list each by place, extent, and cost. Next build targets that costing clarity (your mosaic / porcelain example).

Client document · BOS-32

Can the final document include internal elevations showing the type and extent of tiling, with each elevation referenced to the corresponding wall in the 3D model? This would help the client and contractor understand exactly which surfaces are to be tiled and where each finish starts and stops.

Queued — wave 4

Action:

Wall elevations exist for editing; they are not yet exported as client-document pages tied to a named wall. Follows finish naming in the costing (BOS-31).

Client document · BOS-33

Tiling should be priced in two clearly identified parts. The first covers the tiling work, including measured areas, installation labour, adhesive, grout, spacers and other installation materials. Its scope should be stated clearly so that the client can see what the installation price includes.

Tile supply allowances — The second part is the allowance for supplying the tiles. Separate allowances may be required for different tile types, such as porcelain, ceramic or mosaic. Each allowance should be linked to the relevant area or finish so that the client can understand the basis of the price.

Queued — wave 4

Action:

PC allowances exist for unchosen products; the tender does not yet split installation total from supply allowance per tile type. That split is queued before sales copy.

Client document · BOS-34

A low tile supply allowance can reduce the apparent tender total, while the final cost remains dependent on the client’s selection. This can make a tender appear cheaper at the outset and lead to an increase when the actual tiles are chosen.

Our sales message is that the builder can make these allowances transparent from the outset. By showing the installation costs and tile supply allowances clearly, the builder puts the client in a better position to compare competing tenders on a consistent basis and understand the effect of later selections.

Blocked

Action:

We will add this plain-language paragraph to the client document once installation and supply are separate lines (BOS-33).

Needed to unblock: BOS-33 completed.
